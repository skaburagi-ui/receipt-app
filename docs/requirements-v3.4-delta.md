## 仕様の修正・具体化（Ver.3.3の該当節）

### §3-2／§3-3 入力・モード
- **モード選択は質問形式**：「インボイス登録番号をお持ちですか？」→持たない＝一般／持つ＝適格請求書（または、不特定多数向けの小売・飲食等なら適格簡易請求書）。
- **適格請求書**：登録番号・宛名（空欄・「上様」・敬称のみは不可）・取引日・税率ごとの税込または税抜合計・税率ごとの消費税額・但し書き（内容）が必須。不足なら発行停止。「入力した登録番号は私自身のものです」の確認必須。
- **適格簡易請求書**：登録番号・取引日・内容・税率ごとの合計・「税率または税額のどちらか」が必須。宛名は任意（「上様」可）。対象事業の自己確認必須（判定ロジックは持たない）。
- 適格系の「年月日」は**取引日**を印字する。
- 登録番号は入力を正規化（全角→半角、ハイフン・空白除去、先頭T）し、形式（T＋13桁）を検証。**チェックデジットは法人番号形式の場合のみ警告**（個人事業者は形式のみ）。存在確認（国税庁Web-API）はPhase 2以降。
- **端数処理**：書類単位×税率ごとに1回。方法（切捨て／四捨五入／切上げ）は発行者設定、既定は切捨て。明細ごとの端数処理の合計は禁止。税込は×10/110（8/108）、税抜は×10/100（8/100）。税込・税抜は1書類内で統一。
- 明細区分：{課税10%、課税8%（軽減）、非課税、不課税、免税}。税率別合計には課税明細のみ。**マイナス明細（値引・返品）はPhase 1非対応。**
- 印紙税の判定入力を追加：課税事業者／免税事業者／不明、営業に関する受取か、売上代金か、交付方法（紙／電子）、支払方法。

### §3-6 印刷形式
1. A4縦（210×297mm）1件　2. **A5横（210×148mm）**1件　3. **A4縦に210×148.5mmを上下2件（別々の2件。奇数件は最終ページの下半分を空欄）**　4. A4縦：上=領収書、下=控え
- 重要要素（文字・罫線・角印）は用紙端から**8mm以上内側**（最低6mm）。裁断ガイドも端から5〜8mmに収める。
- 実寸対策：PDFの`PrintScaling=None`（可能なら）、**試し刷りページ**、画面上の環境別の印刷手順。
- 収入印紙の貼付欄は**正本のみ**に置く（控えには置かない）。
- 内容が枠に収まらない場合は、最小フォントまで自動縮小→なお溢れるなら警告して発行（PDF出力）を止める。

### §3-8／§3-12 一括発行
- 1回あたりの上限は暫定300件（実測で確定）。CSV：UTF-8（BOM有無）／Shift_JIS／UTF-16LE。貼り付けはタブ区切り固定。5MB・300行まで。
- 適格請求書モードでは、宛名の空欄・「上様」を**エラー**にする。一括でも書類ごとに端数処理する。

### §3-10 発行・訂正・取消
- 「発行確定」＝利用者のボタン操作。入力値のスナップショット＋テンプレート版数を保存する（Phase 2。Phase 1のデータ型から同じ形で持つ）。
- 訂正書面には、元の書類の日付・番号と修正箇所（正／誤）を印字する。ゲストの訂正は元の日付・番号を手入力。
- 取消は「無効扱い（内部管理）」と表示する。買手への法的効果はないため、訂正書の交付を案内する。

### §3-1／§3-11 ゲスト・保存
- 下書き保存：既定OFF、IndexedDB、30日で自動期限、「すべて削除」、JSON書き出し／読み込み。発行者情報を含めて「毎回入力しない」導線を兼ねる。Safariでは約7日間操作がないと消えることがある旨を案内する。
- **保存の案内**を表示：写し（控え）の保存は利用者の責任。適格請求書発行事業者には写しの原則7年保存の義務がある。
  - 画面：保存・印刷の**前**から見える常設表示（出力ボタンの近く）と、保存後の案内。
  - PDF：受取人に渡す領収書面には載せない（不自然なため）。**「領収書＋控え」形式の控え面の下部に、小さく**載せる。他の形式のPDFには載せない。（2026-11-06 QA2指摘H2への対応。要・発注者確認）

### §5 フェーズ
- 利用規約・免責・出典表示は**Phase 1の限定テスト公開時点から**表示する。Phase 2は招待制（非公開）から開始する。

### §6 技術（確定）
- Workers + Static Assets（Pagesは使わない）／React＋Vite／**ブラウザー内PDF生成：pdfkitを直接使用＋静的TTFサブセット（Noto Sans/Serif JP）**／サーバー側PDF生成は不採用／pdf-libは日本語サブセットで不具合のため使わない／プレビューとPDFは共通の描画リストから生成／Web Worker実行。実装で使わないpdfmakeは依存に含めない。
- CSP（`connect-src 'self'`）を必須とし、外部通信ゼロを検証する。
- Phase 2：Hono＋D1（単一DB）／Better Auth 1.7系（不合格時は自前最小）／メールはResend（独自ドメイン必要、承認後）／所有モデルは作業領域（共同管理の拡張に備える）。

### §7 セキュリティ
- 「運営者は通常閲覧しない」は**運用ルール**であり技術的強制ではない旨を明記する。サポート閲覧は管理画面経由、期間・範囲・操作履歴を記録（Phase 3で最小実装）。

## Phase 1 完成判定基準
1. 初めての人が、単票の入力開始からPDF保存まで数分以内に迷わず完了できる。
2. 実寸印刷で、100mm目盛が99〜101mm、A4二等分が148.5±1mm、8mm枠が欠けない（**実機プリンターでの確認は人間が行う**）。
3. 税務テスト（`docs/review/worker-B-tax-legal.md` §4の検証値ほか）が全通過。不足時に適格系の発行が止まる。
4. 通信観察で、個人情報を含む外部送信が0件。
5. 免責・保存案内・出典表示が画面とPDFにある。
6. 独立した品質レビューで、重大指摘が残っていない。
